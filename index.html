Tracks, sectors and blocks

A standard Amiga floppy has 80 cylinders. Each has two tracks, one per side (head 0 and head 1), and each track holds 11 sectors of 512 bytes. That makes 1,760 blocks and 901,120 bytes, which is exactly the size of an ADF file. The ADF stores the blocks in order: cylinder 0 head 0, cylinder 0 head 1, cylinder 1 head 0, and so on. On the map, each row is one cylinder: head 0 on the left, head 1 on the right.

The Amiga reads a whole track at once. That is why it fits 11 sectors where a PC fits 9. An HD disk has 22 sectors per track.

The boot block (blocks 0–1)

It starts with DOS and a flags byte: 0 means OFS, 1 FFS, 2 and 3 add "international" name handling, and 4 and 5 add a directory cache. Then come a checksum, a root block pointer, and boot code. At power-on, Kickstart reads these 1,024 bytes and checks the checksum. If it is right, Kickstart runs the code. Standard code just starts AmigaDOS. Games often load their own code straight from the disk instead (a trackloader), and some disks carried boot block viruses.

The root block (block 880)

It sits in the middle of the disk, so the drive head never has to travel more than half the disk to reach it. It holds the disk name, dates, a pointer to the bitmap, and a hash table with 72 slots.

Finding a file: hash tables and chains

To find Startup-Sequence, AmigaDOS turns the name into a number from 0 to 71 (its hash) and looks in that slot of the folder's hash table. The slot points to a header block. If several names share a slot, each header has a "next in hash chain" pointer to the next one. Folders are header blocks with their own hash table, so the tree can go as deep as you like.

Files: header, extension and data blocks

A file header holds the name, size, protection bits, date and comment, and lists up to 72 data block numbers. The list is filled from the end backwards. Bigger files continue in extension blocks, each listing 72 more.

In the Original File System (OFS), each data block starts with a 24-byte header (owner, sequence number, size, next block), leaving 488 bytes for contents. The Fast File System (FFS) drops that header, so all 512 bytes hold data.

The bitmap

One bit for every block from block 2 onwards: 1 means free, 0 means in use. If the "bitmap valid" flag in the root block is not set, AmigaDOS rebuilds the bitmap by walking every file (the "validating" you see when you insert a disk that was not safely ejected).

Checksums

Header, extension, OFS data and bitmap blocks each carry a checksum. It is chosen so that all 128 longwords of the block add up to zero. The boot block uses a different sum that carries overflow back in. If you edit bytes in Edit mode, use Fix checksum afterwards, or the Amiga will see the block as damaged.

Non-DOS disks

Many games skip AmigaDOS completely. Their boot code loads raw tracks in the game's own format, often with copy protection, so there is no file system to show. The map then shows which blocks hold data and which are empty. The boot block and its disassembly are still the place to start.
